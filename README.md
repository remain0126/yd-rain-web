## 2. 아이콘 — 로고를 벡터로 추출해 선명하게

원본 logo.png 는 372x324 라, 512 캔버스를 88% 채우려면 451px 가 필요해
1.21배 확대가 일어났다. 확대하면 없는 정보를 만들어내므로 흐려진다.
특히 아래 영문이 뭉갰다.

이 로고는 단색 면 4개(금색/흰색/회색/청회색)로만 되어 있어 벡터로
추출할 수 있었다.

- 색을 4개 층으로 분리
- 각 층을 6배로 키워 이진화한 뒤 potrace 로 경로 추출
- 하나의 SVG 로 합침 (public/logo.svg)
- 아이콘마다 필요한 크기로 SVG 에서 직접 렌더링

확대가 아예 일어나지 않는다.

| 파일               | 로고 렌더 크기 | 캔버스 대비 |
|-------------------|--------------|-----------|
| icon-192          | 169x147      | 88%       |
| icon-512          | 451x393      | 88%       |
| icon-maskable-192 | 138x120      | 72%       |
| icon-maskable-512 | 369x321      | 72%       |

512 도 88% 를 채우면서 선명하다. 앞서 73% 로 줄였던 것을 되돌렸다.

purpose 를 나눈 이유는 안드로이드 어댑티브 아이콘이 항상 잘라내기
때문이다. maskable 은 사각 배경 + 72% 로, 원형으로 잘려도
"영덕소방서" 글씨가 살아남는다.

public/logo.svg 도 같이 넣었다. 지금은 쓰이지 않지만, 앞으로 인쇄물이나
큰 화면용이 필요할 때 크기 제한 없이 뽑을 수 있다.

## 3. _warning.js — 애니메이션과 무관, 판단 필요

특보 조회 결과를 인스턴스 사이에 공유하는 캐시.

getWarning 은 메모리 캐시만 썼다. Netlify 는 인스턴스를 여러 개 띄우므로
화면 요청은 대부분 캐시를 못 맞고 매번 기상청을 새로 불렀고, 그 조회가
최대 3.5초여서 /api/rainfall 응답이 1~3.5초를 오갔다.

1분 감시(/api/watch)가 이미 특보를 새로 받으니, 그 결과를
kma-warning-latest 키에 남겨 화면 요청이 재사용한다. 유효시간 90초 --
감시 주기보다 조금 길게 둬서 감시가 멈추면 직접 조회로 돌아간다.

응답 속도 개선이므로 남겨 두었다. 원래 애니메이션에도 도움이 된다
(응답이 빨라지면 stage-in 해제 시점을 덜 넘긴다).
빼려면 이 파일만 안 올리면 된다. 나머지와 독립적이다.
