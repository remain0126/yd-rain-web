# 영덕군 강우상황 모니터링

영덕군 관내 읍면 강우량과 119안전센터별 위험도를 모바일에서 보는 PWA.
GitHub 연동으로 Netlify에 자동 배포됩니다.

## 구조

```
yd-rain-web/
├─ netlify.toml
├─ package.json
├─ netlify/functions/
│   ├─ _scrape.js            # 영덕군청 페이지 파싱 (파싱만)
│   ├─ _history.js           # 시간별 이력 누적 저장 (Netlify Blobs)
│   ├─ _tiers.js             # 강우 단계 기준 (극한호우 포함 4단계)
│   ├─ _build.js             # 파이프라인: 긁기 -> 이력 병합 -> 창 계산 -> 판정
│   ├─ rainfall.js           # 사용자 접속 응답 (/api/rainfall)
│   ├─ scheduled-refresh.js  # 5분마다 자동 수집 + 이력 누적
│   └─ diag.js               # 진단용 (/api/diag)
└─ public/                   # 프론트엔드 (PWA)
```

## 핵심: 자정을 넘는 누적 계산

영덕군청 페이지는 **당일 01~24시**만 제공하고 어제의 시간별 값은 주지 않는다
(전날누적 = 어제 하루 총합 하나뿐). 그래서 새벽 2시에 12시간 누적을 구하려면
어제 15~24시 값이 필요한데 그 정보가 원본에 없다.

→ `scheduled-refresh.js`가 **5분마다 시간별 값을 Blobs에 누적 저장**하고,
`_history.js`가 그 이력을 이용해 **연속된 시간축**으로 창을 계산한다.
따라서 23시부터 쏟아진 비도 자정을 넘겨 정확히 3시간/12시간 누적에 반영된다.

이력은 48시간치만 보관한다.

## 강우 단계 기준 (`_tiers.js`)

| 단계 | 발령기준 | 조건 |
|---|---|---|
| 극한호우 | 극한호우 | 3시간 90mm↑ **AND** 1시간 50mm↑, 또는 1시간 72mm↑ 즉시 |
| 호우경보 | 호우경보 | 3시간 90mm↑ 또는 12시간 180mm↑ |
| 호우주의보 | 호우주의보 | 3시간 60mm↑ 또는 12시간 110mm↑ |
| 관심단계 | 관심단계 | 3시간 30mm↑ 또는 12시간 60mm↑ |

기준을 바꾸려면 `_tiers.js`만 수정하면 된다 (프론트는 서버에서 기준표를 받아 표시).

## 배포

GitHub 저장소에 파일을 올리면 Netlify가 자동 배포한다.
(Netlify Blobs는 GitHub 연동 배포에서만 동작한다 — 드래그 배포로는 크래시 남)

## 확인

- 사이트: `/`
- 데이터 API: `/api/rainfall` (JSON)
- 강제 최신: `/api/rainfall?fresh=1`
- 진단: `/api/diag`

## 주의

- 도입 초기에는 이력이 아직 쌓이지 않아 12시간 창이 불완전할 수 있다.
  이 경우 화면에 "누적 이력이 아직 부족" 안내가 표시된다.
  5분 주기 수집이 12시간 이상 돌면 완전해진다.
- 참고용 자료이며 공식 특보는 기상청 발표 기준을 따른다.
